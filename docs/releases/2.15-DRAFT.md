## Summary

2.15 introduces native MCP (Model Context Protocol) as the default terminal/host-control path for
Open WebUI, replacing the bespoke Open-Terminal-OpenAPI integration for every real, terminal-capable
production profile (`ki-stack-it-technik`, `ki-stack-18bravo`, `roleplay`, `ki-stack-allgemein`).
Open Terminal itself is not removed, forked, or deprecated-and-broken -- it remains fully installed,
supported, and runnable as an explicit fallback, with a real, proven rollback path in both directions.

## New: MCP Runtime component

- `tools/mcp-runtime/current/` -- a self-contained ("isolation A") Complete Installer component,
  installed/upgraded/repaired/skipped the same way as Open Terminal and Codex Local.
- Runs `open-terminal mcp --transport streamable-http` via `uv run --with open-terminal[mcp]==0.11.34`
  (version-pinned in 2.15 Phase 7 to the one version resolved throughout every test in this cycle),
  bound to `127.0.0.1:8021`.
- Registered in Open WebUI's generic `tool_server.connections` (type `mcp`) as
  `server:mcp:ki-stack-mcp-runtime` -- the standard, non-forked MCP client path, not a dedicated
  terminal mechanism.
- Exposes 12 real tools: `run_command`, `get_process_status`, `kill_process`, `send_process_input`,
  `list_processes`, `read_file`, `write_file`, `replace_file_content`, `list_files`, `glob_search`,
  `grep_search`, `display_file`.
- Same DPAPI-protected local credential pattern as Open Terminal (never plaintext, never in the
  repository), vendored into its own `Vendor/` folder per the established Category-A self-containment
  rule.

## Migrated: production terminal-capable profiles

All four real, terminal-capable Open WebUI profiles now carry `server:mcp:ki-stack-mcp-runtime` in
their `toolIds`, verified via real chat-completion tool calls (not just configuration presence).
`capabilities.terminal:true` is deliberately left in place on all four as an explicit, proven rollback
capability, not a forgotten legacy flag. `ki-stack-research` (no terminal access by design) correctly
carries no MCP binding (`mcpBinding:false`).

## Fixed: Agent Pack toolIds preservation

`OpenWebUIAgentPack.psm1`'s reconcile logic previously regenerated a profile's `toolIds` entirely from
its own definition and extension-tool list on every Upgrade/Repair, with no awareness of the MCP
binding appended outside that mechanism -- a future, entirely routine Agent Pack run would have
silently reverted the MCP migration. Fixed via a `mcpBinding`-gated toolIds addend that survives
reconcile; verified against production with zero drift.

## Fixed: Open Terminal registration credential drift

A real, pre-existing bug (found during 2.15 Phase 6 testing, unrelated to MCP itself): Open WebUI's
`terminal_server.connections` registration can go stale if Open Terminal's own DPAPI credential is
ever regenerated out-of-band, causing every legacy tool call to fail with `HTTP 401` while the
component itself stays healthy. Fixed with a new, narrow, idempotent action:
`Invoke-KIStackOpenTerminal.ps1 -Action SyncRegistrationCredential` -- repairs only the `key` field of
the existing registration, never re-registers, never logs the key.

## Added: LM Studio runtime baseline check

`Test-KIStackLMStudioRuntimeBaseline.ps1` -- a read-only acceptance check for LM Studio's
"Max Concurrent Predictions" setting (root cause of a previously diagnosed latency issue), classifying
3/2/1/unreadable as PASS/WARN/WARN/WARN. Never sets the value automatically.

## Fixed: cutover-runtime post-Execute compliance detection

A real, successful, elevated Execute of `cutover-runtime` (real target, `status:Completed`,
`exitCode:0`, live marker correctly written) was still reported non-compliant by every subsequent
Audit, because the installer's version-detection function unconditionally preferred a frozen,
historical acceptance snapshot over the component's own real, live, per-target marker. Fixed with a
narrow, `cutover-runtime`-only check that reads the live marker first when present, falling back to
the exact same historical snapshot otherwise; verified via a full, genuine Execute run afterwards
(`status:Completed`, all components `exitCode:0`, `cutover-runtime` and `mcp-runtime` both
`compliant:true`). `mcp-runtime`, Agent Pack profiles, and every other component in that snapshot are
untouched.

## Security: local credential hygiene

The repository's secret scan flagged a real, local (never git-tracked) plaintext exposure of the
shared OpenWebUI admin bootstrap credential in Claude Code's own permission cache. Resolved by
rotating the credential via the already-existing `Initialize-KIStackOpenWebUICredential.ps1 -Rotate`
path and removing the stale plaintext entries. See the implementation report's Security Notes section
for the full account.

## Known open items

- Legacy Open Terminal path is not removed in this release and has no removal date yet.
- MCP tool-server registration (like Open Terminal's own OpenAPI registration before it) is still a
  one-time manual step under Open WebUI's Admin Settings -> Tools, not automated by the Complete
  Installer.
- LM Studio's "Max Concurrent Predictions" was found regressed to `1` (known queue-latency pattern)
  during this cycle's baseline check; not auto-corrected, left for manual attention.
- `production-target-acceptance`'s own audit/execute path is separately blocked by a missing historical
  build artifact, unrelated to `mcp-runtime` -- not fixed, out of scope for this cycle.
- The actual release act (tag, push, PR, GitHub Release) has not been performed -- deliberately, as a
  separate step for the user to trigger when ready.
