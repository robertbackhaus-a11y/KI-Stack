# KI-Stack RAG 0.3.0

Development ingestion module for OpenWebUI 0.11.0. Nomic is the only embedding model. Document and query prefixes are separate. Sources are explicit, hash-controlled and removable by stable `source_id`.

`Config/sources.json` is the explicit source allow-list. Audit, DryRun and Status never mutate the target. Execute creates or reuses one managed Knowledge collection, uploads deterministic local chunks with the complete metadata contract, performs SHA256 delta replacement and removes deleted sources. Tokens are accepted only as `SecureString` and are never stored.

OpenWebUI endpoint contracts are pinned to 0.11.0. Add/Query/Replace/Remove have passed real target-system validation. Remote Rollback (of Add) has passed real target-system validation as well, including idempotency on a repeated call: verified against a live OpenWebUI 0.11.0 instance with before/after evidence (remote file genuinely deleted, not merely detached; knowledge collection file listing empty afterward; local state and rollback-archive consistent). Rollback of Replace/Remove is additionally covered by the extensive mocked regression suite but has not yet been separately exercised against a live target.

OpenWebUI 0.11.0 has no collection- or knowledge-scoped embedding contract at all: `RAG_EMBEDDING_ENGINE`/`RAG_EMBEDDING_MODEL` are a single, application-wide setting changed via `POST /api/v1/retrieval/embedding/update`, and `RAG_EMBEDDING_CONTENT_PREFIX`/`RAG_EMBEDDING_QUERY_PREFIX` are fixed at OpenWebUI process startup from environment variables, with no runtime API to change them at all. This is source-confirmed against the actually installed `open_webui-0.11.0` package (`routers/retrieval.py`, `models/knowledge.py`, `config.py`), not inferred from the UI. KI-Stack RAG treats this as a hard platform boundary, not a defect to route around: every mutation of the global embedding config is idempotent (skipped once the target is already active), always preceded by a full non-sensitive backup, and only ever auto-restored on Execute failure or a successful Rollback when that backup provably held no omitted credential value. When a real credential was present beforehand, the config is deliberately left at RAG's own working state instead of a broken partial restore, and the result reports `EmbeddingRestoreRequiresManualAction` naming the previous provider/engine/model -- never a secret value.
