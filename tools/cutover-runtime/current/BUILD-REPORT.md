# KI-Stack Cutover v1.6.13 Source Report

- Basis: Cutover v1.6.2
- GitHub-Repository-Validator unterstützt `version` und Legacy-`packageVersion`
- StrictMode-sichere Manifest-Feldauflösung ohne direkten Zugriff auf optionale Properties
- Schema-Fixtures für current, legacy, dual, conflict und missing
- Release-Manifest enthält kompatiblen Alias `packageVersion`
- GitHub Update v0.5.3 integriert
- 1.6.11: `Modules/06-Applications/KIModuleApplications.psm1` -- der generierte `Start-KIStack-LMStudio.cmd`-Starter entfernt jetzt vor jedem Serverstart best-effort einen konkurrierenden LM-Studio-Electron-Autostart-Eintrag (`HKCU:\...\Run\electron.app.LM Studio`) über denselben eng gemusterten, sicherheitsgeprüften Vertrag, den `Install-KICompleteOperations` bereits für Install-/Upgrade-/Repair-Transaktionen verwendet -- Defektkorrektur, kein neuer Startpfad.
- 1.6.12: `Modules/06-Applications/KIModuleApplications.psm1` -- derselbe Cleanup-Vertrag wird jetzt zusätzlich ein zweites Mal ausgeführt, nachdem der LM-Studio-Endpunkt (`/v1/models`) erfolgreich erreichbar ist, unmittelbar vor `exit /b 0`. Realer Zielsystem-Nachweis zeigte, dass `lms server start` selbst den Autostart-Eintrag nach dem vorherigen Pre-Start-Cleanup erneut erzeugt -- Defektkorrektur (Steady-State-Guard war zeitlich unvollständig), kein neuer Startpfad; der Timeout-/Fehlerpfad bleibt unverändert und führt den zusätzlichen Cleanup nicht aus.
- 1.6.13: `Modules/06-Applications/KIModuleApplications.psm1` -- Open WebUI wird bei `Install-KIModuleApplications`/`Validate-KIModuleApplications` nicht mehr allein wegen exakter Versionsabweichung neu installiert bzw. als nicht konform gemeldet. Neue `Get-KIOpenWebUIVersionSupportState`/`ConvertTo-KIOpenWebUISemanticVersion` (analog zum bereits bestehenden ComfyUI-Supported-Version-Vertrag) trennen `ReferenceMatch` (exakt `0.11.0`) von `Supported` (`>= MinimumSupportedVersion`, optional `<= MaximumSupportedVersion`); `kernel-config.json` trägt neu `applications.openWebUI.minimumSupportedVersion`/`maximumSupportedVersion`. Realer Zielsystem-Nachweis zeigte ein automatisches `pip uninstall open-webui-0.11.1` + `pip install open-webui==0.11.0`, obwohl `0.11.1` eine neuere, unterstützte Installation war -- Defektkorrektur (kein automatisches Downgrade mehr), kein neuer Installationspfad; Greenfield und "unter Mindestversion" installieren weiterhin über denselben, unveränderten pip-Pfad exakt die Referenzversion.
